Homebrew 入门指南：macOS 软件包管理与常用命令速查

从零认识 Homebrew，掌握 macOS 软件安装、查询、更新、卸载、清理和 Brewfile 批量管理。

Homebrew 入门指南：macOS 软件包管理与常用命令速查

在 macOS 上安装开发工具时，我们经常会看到这样的命令：

1

brew install git

这里的 brew 就是 Homebrew，一个帮助我们在终端中管理软件的包管理器（Package Manager）。使用它，可以用统一的命令安装、升级、查询和卸载开发工具及部分桌面应用。

本文整理了 Homebrew 的基本概念、常用命令和日常维护方法，也记录了一些容易踩坑的地方，供以后快速查阅。

1. Homebrew 是什么？

Homebrew 是主要用于 macOS、也支持 Linux 的包管理器。它负责查找软件包、解析依赖、下载和安装软件，并记录由它管理的安装内容。

例如：

1
2

brew install wget            # 安装命令行工具
brew install --cask visual-studio-code  # 安装桌面应用

与从网页下载 .dmg 或 .pkg 文件相比，Homebrew 的优势在于命令统一、便于批量管理，并且可以通过脚本记录所需软件。

Formula、Cask 和 Tap

概念用途示例
Formula通常用于命令行程序、库和开发工具git、wget、python
Cask通常用于 macOS 图形化应用visual-studio-code、firefox
Tap第三方或额外的软件包仓库homebrew/cask-fonts 等（以当前仓库是否存在为准）

Formula 和 Cask 是不同的软件包类型。brew install 可以自动解析很多包名，但显式指定 --formula 或 --cask 更清晰。

2. 安装 Homebrew

2.1 检查是否已安装

1
2
3

brew --version
which brew
brew --prefix

如果能看到版本号，说明 brew 命令已可用；brew --prefix 可以显示当前 Homebrew 的安装前缀。

2.2 首次安装

在终端执行官方提供的安装命令：

1

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

安装前最好先查看 Homebrew 官网 的最新说明，并确认脚本来源。根据机器配置，安装程序可能提示安装 Xcode Command Line Tools。

常见的默认安装位置：

设备默认路径
Apple Silicon（M 系列）/opt/homebrew
Intel Mac/usr/local

安装完成后，按照终端提示设置 shell 环境。对使用 Zsh 的 Mac，可根据实际安装路径配置 ~/.zprofile，例如 Apple Silicon 的典型情况：

1
2

echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
eval "$(/opt/homebrew/bin/brew shellenv)"

Intel Mac 的默认前缀则通常为 /usr/local。如果 brew 已可用，不需要重复追加配置。

兼容性提醒： Homebrew 对不同 macOS 版本、CPU 架构的支持级别不同。特别是较旧的 Intel Mac，可能缺少预编译包（Bottle），导致安装需要本地编译甚至失败。安装前可查看 官方支持级别。

3. 常用命令速查

3.1 搜索和查看软件

1
2
3
4
5
6

brew search python          # 搜索软件
brew info python            # 查看软件说明、版本及依赖
brew list                   # 列出已安装软件
brew list --formula         # 仅列出 Formula
brew list --cask            # 仅列出 Cask
brew --prefix python        # 查看某个 Formula 的安装前缀

3.2 安装软件

1
2
3

brew install git            # 安装 Git
brew install wget jq        # 一次安装多个软件
brew install --cask firefox # 安装图形应用

安装前可以先用 brew info <名称> 查看对应版本、依赖与要求。

3.3 更新 Homebrew 与软件

这是最容易混淆的一组命令：

1
2
3
4
5

brew update                 # 更新 Homebrew 与包元数据
brew outdated               # 列出可升级的包
brew upgrade git            # 只升级 Git
brew upgrade                # 升级符合条件的已安装包
brew upgrade --cask firefox # 升级指定 Cask

brew update 不等于 brew upgrade。 前者刷新软件包信息，后者才真正升级已安装软件。brew upgrade 可能涉及依赖更新及应用重装，建议先查看 brew outdated，尤其不要在科研实验或生产环境运行期间盲目批量升级。

有些 Cask 应用自身也带有更新器，因此它们的升级行为可能不完全由 Homebrew 控制。

3.4 卸载软件

1
2
3

brew uninstall wget         # 卸载指定软件
brew uninstall --cask firefox  # 卸载图形应用
brew autoremove             # 移除不再需要的依赖

brew uninstall --cask --zap <名称> 还可能删除应用相关配置与用户数据，使用前务必确认，不宜当作常规卸载命令。

3.5 清理和检查

1
2
3
4

brew cleanup -n             # 预览可以清理的内容
brew cleanup                # 清理旧版本和缓存等
brew doctor                 # 检查常见环境问题
brew config                 # 查看 Homebrew 和系统配置

brew doctor 的警告需要结合环境判断；有警告不代表所有软件都不能使用。brew cleanup 可能清除旧版本，因此在需要回退的环境里应先评估。

4. 进一步管理软件

查看依赖

1
2

brew deps python            # 查看 Python 依赖
brew uses --installed openssl@3  # 查看已安装软件中哪些依赖它

重新安装和锁定版本

1
2
3

brew reinstall git          # 重新安装
brew pin git                # 阻止常规升级该 Formula
brew unpin git              # 取消锁定

pin 不是完整的版本管理工具，也不能保证所有依赖操作都不触及对应软件。若项目需要严格固定 Python、Node.js 等运行时版本，应考虑专门的版本管理器或隔离环境。

管理后台服务

部分软件（例如数据库）支持以后台服务形式运行：

1
2
3
4

brew services list
brew services start postgresql@17
brew services stop postgresql@17
brew services restart postgresql@17

这里的 postgresql@17 只是示例，实际安装的 Formula 名称和版本可能不同。运行前用 brew info 确认。

5. 使用 Brewfile 批量管理软件

如果需要迁移电脑、重建开发环境，逐个安装软件很麻烦。Homebrew Bundle 可以把软件清单写入 Brewfile。

在希望保存清单的目录中执行：

1

brew bundle dump --file=Brewfile   # 导出当前安装清单

一个简单的 Brewfile 可能是：

1
2
3
4
5

brew "git"
brew "wget"
brew "jq"
cask "visual-studio-code"
cask "firefox"

在另一台电脑上执行：

1
2

brew bundle check --file=Brewfile   # 检查是否满足清单
brew bundle install --file=Brewfile # 安装清单内软件

注意： Brewfile 是软件清单，不一定能精确锁定所有软件版本。brew bundle install 默认可能升级现有软件；如果不希望其主动升级过时依赖，可考虑 brew bundle install --no-upgrade --file=Brewfile，但仍需关注依赖解析和版本兼容问题。

此外，Brewfile 可能暴露已安装的个人软件名称。提交到公开仓库前，建议检查内容。

6. 常见问题与排查

Q1：zsh: command not found: brew

先检查安装路径：

1

ls /opt/homebrew/bin/brew /usr/local/bin/brew 2>/dev/null

如果 Homebrew 已安装但找不到命令，按安装器提示为当前 Shell 配置 brew shellenv。不要直接复制另一台电脑的绝对路径。

Q2：升级时出现大量 Outdated Formulae / Casks

这只是说明部分软件有可用更新，并不要求立刻升级全部软件：

1
2
3

brew outdated
brew info bash
brew upgrade bash

建议优先升级有明确需求的软件，检查更改是否会影响现有项目。特别是在旧 Intel Mac 上，应先确认预编译包与系统支持情况。

Q3：遇到 undefined method、下载失败或安装异常

先收集诊断信息：

1
2
3
4

brew --version
brew config
brew doctor
brew update

如果依旧失败，查看完整错误信息和 Homebrew 的相关 Issue。此类异常不一定是目标软件本身的问题，也可能来自 Homebrew 代码、缓存、依赖或平台兼容性；不建议直接删除整个 Homebrew 目录。

Q4：为什么升级过的软件仍不是终端调用的版本？

系统中可能同时存在多个同名命令。例如 macOS 自带 Bash，而 Homebrew 安装的 Bash 通常位于另一目录：

1
2
3

which -a bash
/bin/bash --version
"$(brew --prefix)/bin/bash" --version

升级 Homebrew 的 bash 不会替换 系统的 /bin/bash。若脚本使用 #!/bin/bash，它仍会运行 macOS 自带版本；要使用新版 Bash，应明确选择其解释器路径，并考虑其他设备上的可移植性。

7. 推荐的日常维护流程

日常不必每次都运行全量升级。我更倾向于先检查，再按需求维护：

1
2
3
4
5

brew update                 # 更新软件索引
brew outdated               # 查看待升级项目
brew upgrade <package>      # 只升级需要的软件（替换占位名称）
brew cleanup -n             # 先预览清理内容
brew doctor                 # 出现异常时检查环境

对于稳定运行的科研或开发环境，可复现性通常比始终使用最新版更重要。项目依赖尽量通过 requirements.txt、pyproject.toml、锁文件或容器等独立管理，不要把系统包管理和项目依赖管理混为一谈。
